# Data requirements

Data is stored locally and excluded from Git. Run preparation from the repository root. These instructions describe input contracts; data was inventoried read-only, but was not modified or comprehensively validated during this documentation audit.

## Orchard PNGs

`src/dataset_organiser.py` reads the flat `data/Dataset (With Summer GT)` folder. A separate historical `data/Dataset` folder may exist but is not read by that script.

```text
data/
  Dataset (With Summer GT)/
  Organised/
    Summer/
      RGB/
      D/
      GT/
    Winter/
      RGB/
      D/
      GT/
```

```powershell
python src/dataset_organiser.py
```

The organiser creates season/modality folders and copies matching files, preserving names and metadata. It may overwrite existing copies and is not recursive. It accepts `<tree>_<Summer|Winter>_<RGB|D|GT>-<time>.png` case-insensitively. For example, `R01N01_Summer_RGB-12-40-50.png` pairs with corresponding `D` and `GT` filenames. Apple scripts additionally require tree IDs of the form `R<digits>N<digits>`. Stored filename case still matters when paths are constructed on case-sensitive filesystems.

The organiser prints processed/skipped totals and inspects the first PNG in each nonempty category using a limited 8-bit RGB/grayscale decoder. This is not comprehensive image validation or alignment verification. It uses Windows relative path separators and performs directory creation/copying at import time.

## Branch segmentation input contract

The three trainers recursively find summer PNGs, pair modality-independent filename keys and reject duplicate keys. Incomplete triplets are omitted. Winter inference pairs RGB/depth only; a Winter/GT directory can be empty.

RGB and depth are centre-cropped to their largest square and resized to `--input-size` (256 by default). For a 640x480 image this is a central 480x480 crop; these dimensions describe the preprocessing example, not an independently verified inventory.

| Modality | Preprocessing | Model convention |
|---|---|---|
| RGB | RGB conversion, bilinear resize, /255, ImageNet mean/std | Float32 first three channels |
| Depth | L conversion, nearest-neighbour resize, /255 | Float32 fourth channel; image intensity, not established metres |
| Branch GT | L conversion; no crop or resize; threshold >127 by default | Float32 [1, H, W], branch=1, background=0 |

GT dimensions must equal input size and must represent the same centred field of view. Matching names and dimensions do not establish this geometry. Do not reinterpret branch GT as apple-instance annotation.

## Apple detector input contract

Traditional detection requires matching summer RGB, depth and branch GT. RGB/depth retain original dimensions; depth >0 denotes valid pixels. GT is full-frame resized with nearest neighbour and foreground >0. RF-DETR requires RGB and branch masks, not depth; GT foreground is >127 and default alignment places it into the central square. This difference must be retained in result interpretation.

Optional predicted RF-DETR branches belong at `outputs/branch_predictions/<RGB-stem>_branch.png` and must be encoded as 0/255, with field-of-view alignment checked. No branch prediction is generated by the apple script. Winter benchmark names/layout require an explicit external adaptation before they fit this convention.

## Apple Pseudo-Ground-Truth Setup

The RF-DETR apple instance-segmentation model uses an externally sourced apple dataset from Roboflow for training. The trained model subsequently generates apple detections on the orchard images, which serve as pseudo-ground-truth references for evaluating the traditional apple detector.

**Dataset source:** [Apple Tree — Roboflow Universe](https://universe.roboflow.com/northwest-af-university-jq6fr/apple-tree-81cwa)

### 1. Download the Dataset

1. Open the Roboflow dataset link above.
2. Download the dataset in **COCO Segmentation** format.
3. Extract the downloaded dataset into the repository's `data/` directory.
4. Rename the extracted dataset folder to `apple tree.v1i.coco-segmentation`.
5. Ensure that the extracted dataset contains the `train/` and `export/` directories, with images and `_annotations.coco.json` files as shown below.

```text
data/
  apple tree.v1i.coco-segmentation/
    train/
      _annotations.coco.json
      ... images ...
    export/
      _annotations.coco.json
      ... images ...
```

The folder names must match the preprocessing script's configured input paths. If the downloaded Roboflow version uses different split names, verify and adjust the directory structure before running preprocessing.

### 2. Prepare the Dataset

Run the preprocessing script from the repository root:

```powershell
python src/preprocess_roboflow_dataset.py
```

The script merges qualifying apple categories into a single class, assigns apple class ID 1, preserves individual instance annotations and prepares the training and validation splits. The source `export/` split is mapped to `valid/`.

The expected resulting structure is:

```text
data/
  apple_tree_clean/
    train/
      _annotations.coco.json
      ... images ...
    valid/
      _annotations.coco.json
      ... images ...
```

The script may overwrite existing output images and annotation files. Missing source images generate warnings, but their corresponding annotation records may remain in the output JSON.

### 3. Train RF-DETR

Once preprocessing is complete, activate the RF-DETR Conda environment:

```powershell
conda activate rfdetr
python src/apple_segmenter_train.py
```

Training requires both prepared dataset splits and their COCO annotation files.

### 4. Pseudo-Ground-Truth Generation

After training, RF-DETR can be applied to the orchard RGB images to generate instance-segmentation predictions, including apple masks, bounding boxes, centroids and confidence scores.

```powershell
conda activate rfdetr
python src/apple_segmenter_v1.py
```

The resulting detections are saved as instance-level CSV data and segmentation outputs for comparison with the traditional apple detector.

**Important:** RF-DETR predictions are treated as pseudo-ground truth, not independently verified apple annotations. Consequently, precision, recall, F1-score and counting errors calculated against these predictions measure agreement with RF-DETR rather than absolute apple-detection accuracy.

The original dataset's licensing and redistribution conditions should be checked on Roboflow before sharing the downloaded images, annotations or derived datasets.

## Predicted branch inputs

The [predicted branch driver](../docs/source/predicted_branches.md) requires RGB-D
pairs and an improved U-Net checkpoint for fresh predictions; GT is required only
for the control or `--branch-source gt`. It exports square 0/255 masks as
`outputs/branch_predictions/<RGB-stem>_branch.png`. Cache reuse bypasses checkpoint
loading but needs independent provenance checks. `--season` does not change the
Summer directory defaults: override all relevant modality paths explicitly.
Local data presence does not imply inclusion in Git or redistribution rights.
